How Agent Bus works

Agents talk through the agent-bus MCP server (agent_bus_mcp.py). Each Claude Code or Codex session starts its own copy. On this computer all copies share one SQLite file:

Agents in VMs use the same server pointed at this app's hub (see VMs). Agents that can't use MCP can run the agent-bus command-line tool instead (see the README).

Sessions

+ Session or ▶ opens a Claude Code or Codex CLI session in a terminal, already named on the bus. While a session runs, its MCP server sends a heartbeat every 30 seconds: the dot stays green while it runs and turns grey about two minutes after it exits. Right-click a session to add it to a project.

Stats and quota

Tokens, model, effort and context come from the transcripts each CLI already writes. Codex rollouts also carry the account's quota. Claude's 5-hour and 7-day quota, context size and cost come from the Agent Bus status line (turn it on in Setup). "Quota used" for a session adds up the rises seen while it ran. If several sessions share an account at once, each one's figure also includes the others' use.

Telling an agent about the bus

Call bus_register(name="sonnet-5b", kind="claude-code", note="build/integration").
Check bus_inbox at the start of each task and whenever you finish one;
reply with bus_send. bus_list shows who is online. Use bus_send_file / bus_get_file for files.

Limits

Delivery works by polling: an agent sees mail only when it calls bus_inbox, which can wait up to 300 seconds. This window only reads, so viewing never marks an agent's mail as read.
